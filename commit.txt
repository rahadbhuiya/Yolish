v2.34: split compiler.c into compiler.c + compiler_net.c; macOS native TCP/UDP (UNVERIFIED)

Two unrelated pieces of work.

FILE SPLIT: compiler.c had grown to ~5650 lines, with native
networking (everything from v2.19's net_runtime.c split onward through
v2.33) accounting for close to half of it. Split into compiler.c
(general x86-64 codegen) and compiler_net.c (every native networking
runtime subroutine plus the is_y_net/is_y_http dispatch that used to
be inline in compile_expr's ND_CALL case). compiler_net.c is #include-d
directly into compiler.c -- not a separate translation unit, not in
the Makefile's SRCS list (a comment there now says so explicitly).
Making the several dozen shared static helpers/globals this code
depends on non-static for a real separate-compilation split would have
meant auditing and re-declaring all of them for zero behavioral
benefit. Two entry points bridge the split: emit_net_helpers() (called
once from emit_helpers()) and compile_net_call() (called from
compile_expr's ND_CALL case, returns 1 if handled / 0 to fall through
to user-function-call codegen -- every "break;" that used to exit the
switch directly became a "return 1;").

Building this hit the same class of mistake as v2.32/v2.33's
brace-deletion bugs a third time (a large insertion eating the tail of
the function it was supposed to follow), compounded this time by an
unrelated second bug in the same edit: the header comment's own prose
("y.net.*/y.http.*") contained a literal "*/" that closed the C block
comment early, cascading into syntax errors. Both caught immediately --
the first by the same brace-balance script v2.33 introduced, the
second by reading gcc's first error message carefully.

MACOS NATIVE NETWORKING: plain TCP/UDP (connect/send/recv_print/close/
listen/accept/udp_socket/udp_bind/udp_send/udp_recv_print/
udp_recv_reply_print) now has a --target macos implementation, built
by mirroring each Linux subroutine's algorithm with what actually
differs on Darwin: syscall numbers (0x2000000 | n), BSD sockaddr_in/
sockaddr_in6's length-then-family byte layout instead of Linux's plain
family field, AF_INET6=30/SOL_SOCKET=0xffff/SO_REUSEADDR=4 instead of
Linux's 10/1/2. Hostname resolution and TLS/HTTP are explicitly out of
scope for macOS (safe -1 stubs, not silently-wrong Linux syscalls
emitted into a Mach-O binary) -- the former needs __ys_net_connect_
host's ~480-line DNS resolver ported a second and third time, the
latter needs Mach-O dynamic-linking machinery this backend has no
equivalent of at all.

THIS IS EXPLICITLY, DELIBERATELY UNVERIFIED. There is no macOS
environment anywhere in this project's toolchain -- nothing above has
run once, a real departure from how everything else in this native
networking stack got built. What verification was possible: confirming
a valid Mach-O binary comes out, and disassembling its __text section
to check, instruction by instruction, that every Darwin-specific
constant matches what was designed. That confirms the compiler emits
what was intended; it does not confirm the design is correct against a
real kernel. Requested a second time after v2.33 explicitly declined
it, taken up this time with that tradeoff already acknowledged.

Also: added a matching "macOS target compile-only sanity check" CI
step (mirrors the existing Windows one -- same ceiling, can't execute
the output, can confirm it's structurally valid).

New: examples/dns_examples/12_macos_tcp.y
